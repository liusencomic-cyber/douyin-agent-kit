# 抖音短链重定向差异：服务器端与客户端可能解析到不同内容

## 现象

同一个 `v.douyin.com/XXXX` 短链：
- **用户 在抖音 APP 中打开**：显示视频 A（例如 FredTalk 的 Codex+Stitch 教程）
- **服务器端用无头浏览器/HTTP 请求解析**：重定向到视频 B（例如《遗忘之海》游戏宣传片）

两者视频 ID 不同，标题、作者、内容完全无关。

## 根因

抖音短链解析受以下因素影响：
- 是否登录抖音账号
- 账号的观看历史/推荐算法
- 客户端类型（APP vs 浏览器 vs 无头浏览器）
- 地区 / IP / 运营商
- 时间 / 短链是否被复用或过期替换

**这不是用户给错链接，而是平台侧的分发/推荐行为。**

## 会话案例

- 2026-07-09：用户 分享 `https://v.douyin.com/XXXXXXX/`，描述为 "FredTalk 用 Codex+Stitch 做前端效果"。服务器端无论用 DynamicFetcher、手机 UA、浏览器 navigate 还是 `urllib.request`，最终都解析到视频 `<示例ID>`《遗忘之海》。画面截帧确认是游戏宣传 CG，无代码/前端相关内容。

## 正确处理方式

当服务器端抓取到的内容与 用户 描述明显不一致时：

1. **不要争辩**。不要反复说 "我这边解析没问题"、"你那边打开不对"、"链接本身没问题"。
2. **直接陈述事实**：服务器端抓到的实际标题、作者、视频 ID 是什么。
3. **提供选项**：
   - 按服务器端实际内容归档（笔记中注明短链重定向差异）
   - 请 用户 在抖音 APP 内打开该视频 → 分享 → 复制 **长链接**（`https://www.douyin.com/video/<ID>` 或 `https://www.douyin.com/note/<ID>`）再发一次
   - 请 用户 直接下载/录屏该视频文件发过来
4. **不要尝试超过两种不同抓取方式后继续纠缠**。如果 HTTP、Playwright、浏览器都返回同一视频，接受这个事实并转向替代方案。

## 归档笔记中的标注

如果 用户 选择按服务器端实际内容归档，在 Obsidian 笔记开头加一段：

```markdown
> ⚠️ 该短链在服务器端解析到的内容与分享描述不一致。服务器端抓取到的是 [实际标题/作者]，
> 可能与抖音短链在不同设备/账号/地区下的重定向行为有关。建议用长链接复核。
```

## 与缓存/假链的区别

- **缓存**：用户 之前看过视频 A，APP 缓存展示 A，但短链实际指向 B。长链接可绕开缓存。
- **假链/串号**：用户复制时确实复制了另一个视频的链接。长链接同样能确认。
- **平台推荐**：未登录/无头环境触发推荐分发，把短链映射到平台认为相关的内容。这是最常见的情况。

无论根因如何，处理流程相同：不争论、给事实、给选项。
